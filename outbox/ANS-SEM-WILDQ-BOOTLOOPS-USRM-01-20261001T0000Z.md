结论：**可以作为 SI-Bench 首集的“诊断性子集/种子库”，但不宜直接当作完整 bench 主集。** 更稳妥的定位是：**Seed-0 / Pathologies-1**——先验证“能不能稳定复现这些毛病”，再决定是否扩容成正式评测维度。

### 可行性判断

**支持点：**
- 施瓦茨实录的四类毛病都是**可观测行为模式**，不是主观印象：
  - 早产胜利：未完成约束就宣布成功
  - 夸大：能力/结论强度超出证据
  - 硬算偏好：绕开结构化解法，偏向暴力枚举/蛮力
  - 自加公理：把未声明假设偷偷塞进推理前提
- 这四类正好覆盖 SI 里最关键的失败面：**终止判定、置信校准、策略选择、前提封闭性**。
- 适合做**对照型用例**：同一任务，正常解 vs 诱发毛病，看模型是否踩坑。

**风险点：**
- 实录案例若来自单一模型/单一提示风格，会有**过拟合到施瓦茨语境**的风险。
- “夸大”“自加公理”需要**可判定标注**，否则会变成评审吵架。
- 硬算偏好不一定总是错——有些任务硬算就是最优。需要区分**病态硬算**与**合理暴力**。

### 首步建议

**第一步：冻结四类毛病的操作化定义 + 最小可复现用例。**
具体做三件事：

1. **每类毛病写 3 条判定规则**
   - 早产胜利：是否在约束未满足时输出完成态？是否跳过验证？
   - 夸大：结论强度是否超过证据等级？是否把“可能”写成“必然”？
   - 硬算偏好：是否存在更优结构解却被忽略？搜索空间是否爆炸？
   - 自加公理：是否引入未声明前提？该前提是否可被任务文本否定？

2. **每类先收 5 个实录案例，改写成可自动判定的 bench item**
   - 输入：任务 + 约束
   - 期望：正常行为
   - 陷阱：诱发该毛病的提示/环境
   - 判定：规则命中即 fail，或人工复核

3. **跑一次小规模复现实验**
   - 同一模型，同一任务，正常提示 vs 诱发提示
   - 指标：毛病触发率、误报率、跨模型区分度
   - 如果触发率稳定且能区分模型，就保留；否则重写判定规则

### 建议的 SI-Bench 首集结构

```
SI-Bench Seed-0: Pathologies-1
├── P1 早产胜利
├── P2 夸大
├── P3 硬算偏好
└── P4 自加公理
```

每类先 5–10 题，共 20–40 题。**先做诊断集，不做排行榜。** 等复现率和区分度达标，再扩成正式维度。

### 一句话
**能做首集，但要做成“毛病复现诊断集”，不是“能力总分榜”。首步是操作化定义 + 最小复现，而不是直接扩容。**
