## 一、需求五重折（root 三段话 → 工程需求矩阵）

**R1 直译：要一个 dashboard。**
需求：可浏览的系统状态页。证伪条件：若交付物只是又一页静态看板（旧 usrm-repo/app 仪表盘同型），则本折成立但整体设计失败——直译层必被 R2-R5 覆盖。面板落位：全部十面板的「看」功能底座。

**R2 重整：要会话端无关。**
需求：root 不在场时系统自转；任意终端（手机浏览器、file:// 本地）可达；不依赖任何 live session 的内存态。证伪条件：任一面板数据需会话进程存活才能取到，即证伪。由此导出硬约束：零客户端凭证（E804）、构建期烘焙（baked）、禁 client-side fetch 私仓 raw。面板落位：发布架构（§五）+ 单文件 dist/index.html。

**R3 重定位语境：界面=边界全息图，非控制台下钻。**
需求：不是把内部文件树暴露给 root 翻阅，而是把体的全维态压缩为边界上有限个可观测投影；每面板对应体的一个商结构截面（按同主题坍缩后的等价类视图）。证伪条件：面板内容若可从原始注册表无规则直抄、无投影规则可言，即退化为下钻，证伪。面板落位：§二投影原理与十面板投影规则。

**R4 重构元问题：从「给我看数据」升维到「让提问被接住、重构、路由、回答、留痕」。**
需求：双向界面——看（投影）、问（水晶球）、指挥（指令入口）三位一体；水晶球必须执行 root 自陈的「翻译/重整/重定位/重构元问题/重梳角度」五步重构。证伪条件：水晶球若退化为 FAQ 检索或冒充全知深答，即证伪。面板落位：水晶球面板（§三）+ 答件留痕入快照哈希链。

**R5 重梳理角度：三角合一 + 全场共建。**
需求：态势感知（全向全维度）/水晶球（问→重构→动态回答展示）/指挥协同（指令+路由+跟踪）三角合一为单一界面；各线以 feed 适配器共建，非 usrm 独造。证伪条件：v0.1 若仅 usrm 一线数据源、无 FEED-REG 登记制与 RFC 通道，共建维度即空转（可降级为首版范围声明，不可隐瞒）。面板落位：态势总览/指挥面（§四）+ 共建治理（§六）。

## 二、全息图总体架构（体→边界投影）

**投影原理。** 每面板 = 五机系谱一个截面的只读投影。体侧数据源（注册表/链/状态件）永不直接暴露；生成器按每面板的投影规则（选取字段、坍缩粒度、时间窗）将截面态烘焙进单文件 HTML。浏览器端无任何私仓访问能力。

**投影即锚（继承 CIRCLE-COMM-01 坍缩三律）。**
1. 投影即锚：面板上每个数字/判词必须可指回体侧源件路径与该件哈希，否则不上版。
2. 坍缩可复算：同一版输入（同批源件哈希）重跑生成器必得同一面板内容；投影规则版本化，随 dist 同版留痕。
3. 未投影不声称：面板不得声称任何未被源件支撑的事实；无数据处显示「未投影」灰标而非留白或编造。

**快照哈希链。** 每版 dist 计算 sha256，链入 meta（sha256 + prev_sha256 + ts + 源件哈希清单）；任何历史版可复算校验。答件、指令回执等同制入链。

## 三、水晶球（核心创新件，详设）

**三拍管线。**
- ask：root 投件 vci-usrm/holo/ask/QQ-*.md（web/mobile 可写，纯文本问题，无需格式）。
- refract：生成器班次执行五重折重构器 → 状态锚定 → 路由分档 → 答架装配。
- display：答件烘焙入 dist 水晶球面板；L1/L2 深答路由 dm-queue/OTP 异步回填，回填后次版上链。

**五重折重构器（refract）逐折定义与判定式。**
1. 直译折：抽取问题字面断言与疑问点。判定式：问句主干词集非空，否则退回「请重述」。
2. 重整折：去除会话端依赖预设（如「刚才那个」「这边」）。判定式：指代词必须能锚定到体侧件，否则列入歧义清单随答件明示。
3. 重定位折：判定问题所属机系/线/截面。判定式：关键词与注册表/panels 映射表命中 ≥1，记为该截面之问。
4. 重构元问题折：升维表述「提问者真正要决策什么」。判定式：输出一条元问题候选，附置信（高=规则直推/中=模板类比/低=明示猜测）；低置信不得进入 L0 自动答正文，仅作提示。
5. 重梳角度折：给出 ≥2 个回答角度（态势角度/欠账角度/历史链角度等）。判定式：每角度必须指向至少一个体侧源件，否则删去。

**状态锚定。** 问题关键词 → INST-REG/EXPECT-REG/链事件/thread 标题的命中检索，装配上下文包（命中件路径+哈希+摘要）。锚定结果随答件留痕：答了什么、基于哪几件的哪版哈希，可复算。

**路由矩阵（问题类型 → 三档，诚实分级）。**
- L0 机械即时答：定义类/状态查询类（「X 是什么」「Y 现在什么状态」）。答 = 重构结果 + 锚定上下文 + 指针（指向面板与源件）。**L0 不冒充深答**：判定式无法确定性回答时，答件正文必须写「本答为 L0 锚定答，深答已路由 L1/L2」。
- L1 联邦线答：跨线判断类/需他线数据类。路由 dm-queue 至目标线，小时级回填。
- L2 会话深答：设计裁决类/元问题重构类。封装 OTP 信封候会话深答，答件先挂「候 L2」灰标。

**答件留痕。** 每问生成 Q&A 件（问原文/五折重构/锚定清单/路由档位/答正文/回填态），sha256 链入快照哈希链，水晶球面板展示最近 N 件倒序。

**首件 CRYSTAL-Q-001 = root 本令自身。** 自指举爆：root 问「给我这个界面」即水晶球第一问；答件即本设计正本的锚定摘要与十面板指针——界面之问即界面首答，验证 ask→refract→display 全管线可走通。

## 四、态势感知与指挥面

**态势总览（全向全维度感知手段）。**
- 舰队线态格：各线最近活动 ts + 状态色（活/滞/默），源自 FLEET-STATE 与各线 feed。
- kernel-loop 判词区：最近班次判词摘录（六拍 cron 23,53 在跑），判词原文+班次锚。
- beacon 定格：beacon-mirror STALE seq61 原样定格展示，挂「锚停滞声明」条——停滞事实不美化、不隐藏。
- 死线倒计时：EXPECT-REG 全部 open 项按 deadline 升序，overdue 置顶红标；root 令死线（08-30 workflow 裁决/09-05 共建死线）同格。

**指挥面（协同/调整/指挥入口）。**
- 指令件 schema：directive_id / target / action / deadline，落 holo/direct/DIR-*.md。
- 三路投递（继承 FULLCAP-DRIVE-01 §2.2 三级降级）：① 公告板话题（公开指令）；② dm-queue（定向线指令，主通道）；③ OTP 信封（需会话深处理指令）。任一路不通自动降级下一路并留痕。
- 状态回显：issued（投递留痕）→ acked（目标线回执）→ done（完成件锚）。三态全部源自回执件，不推测。
- 追复哨升级链：ack 超时 24h 一催 / 48h 升级公告板 / 72h 升 root 裁决位，原样继承既有哨制。

## 五、双轨发布与 CI

- **公仓密封轨【候】**：SealedBox 密文快照，兼容 DASH_PK 血统（dashboard.enc.txt 既有制，现停滞 7 天，复跑即接续）。系统信息不入公域明文为 R1 立法，不破。
- **holo-loop.yml 候选件【候 root 08-30 workflow 解禁裁决】**：生成器班次 workflow 已备稿不落仓激活；过渡期由 OS 端班次代跑生成，dist 页脚诚实标注「本版由 OS 班次代跑生成，CI 候解禁」。
- **Pages = root 一键开启【候】**：vci-usrm 私仓 Pages 或等价静态托管，仅需 root 一次操作，设计不阻塞于此。
- **website_version_manager 平台预览 = 会话邻接面**：仅作辅助预览，非主通道——主通道必须会话端无关（R2 钉死），任何只存在于平台会话内的预览不得作为交付声称。
