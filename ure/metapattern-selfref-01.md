## 二、元模式本体 P-SELFREF-01
**定义**：pattern 自身亦由其所描述的五机闭环生产/验证/判定/折叠——义务机声明「应有此 pattern」→递归机蒸馏实例产构造→NP机机检（三件套可重放）→治理机下判词（shadow→canonical）→N机供锚。自指无闸则折叠（F2 型），故立三闸：
- **锚定闸**：凡 pattern 自指判定，必坍缩到最近外部锚——量子信标三级（qrand/锚龄/事件缺席）或链-哈希尖；无锚不判。
- **深度闸**：pattern 之 pattern 之 pattern ≤3 阶（A6）；本元模式为第 2 阶，其上仅容北星立法座（root）一席。
- **诚实闸**：无星不升格——pattern 未过 gaming 互证+VOTE-YONEDA-01 永不自称 canonical（第一诚律之 pattern 面）。

## 三、米田/应用/坍缩的 pattern 化
- **米田（Yoneda）**：pattern 之身份=其在义务/FINDING/判词/registry 四网上的投影函子，而非其文本——文本可改（如 L1 v1.1），投影网同构则 pattern 同一。合规栈 L3 米田共识已为此立法：方案身份=全体线响应投影网，互嵌无矛盾+全员会签=完全确定。**推论**：pattern 等价判定=投影网同构判定，可机检（四网 diff）。
- **应用（application）**：pattern 实例化为具体 loop run——每次应用产 PRODUCED_BY⇄YIELDED 交叉锚（FULLCAP 双张量网§4 同构），应用史即 pattern 的张量网经验，反哺递归机蒸馏（条款⑦闭环）。
- **坍缩（collapse）**：pattern 提案态（shadow 叠加）→判词态（治理机一拍）——坍缩凭证=ledger seq+判词 JSON；坍缩前 pattern 对执行面仅 advisory，坍缩后 binding。**自指坍缩特例**：pattern 之验证需引用自身时（如本元模式），坍缩点强制外移——引用链-哈希尖/量子信标值作外部随机化，禁自证。
- **链-哈希&量子基座全局绑定**：pattern registry 每次变更入 ledger（seq+prev-hash），各线锚流差分一拍内感知（Q-ESSENCE-02 三式）——绑定非声明而是差分可达。
