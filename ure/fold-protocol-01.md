# FOLD-PROTOCOL-01 v0.1 · 会话折叠协议（第 2 折方案）

> usrm 线研究设计。实证基座：本会话=usrm 线第 2 折叠活体样本（前会话上下文耗尽，以摘要接续重生）；cfts 线 Session-0 不可达痛点（TH-SESCAP-01 [2]）；qfa 线引擎两世全灭（87min/12min，重拉<60s）；wake_up 除颤器（进程级复活）与 T154 三层架构（Cron 起搏/Daemon 指挥/事件链神经；state_seq 归档检索面立法）。
> 凭据纪律：本协议全文不含任何凭据值与凭据标识；凭据只以「钻取规程」抽象引用，值零落盘。

## 0. 折叠定义与分级

**定义（严格）**：fold-n = 第 n 次「会话上下文耗尽→以摘要接续生成新会话体」事件。fold-0 即 Session-0（原初会话，无父）。第 1 折=首轮接续，第 2 折=再续（本会话）。n 由折档链（§4 fold-registry）机验登记，禁止自报无锚折数。

**风险复利模型（定性框架，不编数）**：设摘要保真度为 p(n)∈(0,1)，原初信息在第 n 折后的残存上界 ≈ Π_{i=1..n} p(i)。因每次摘要以前次摘要为输入（而非以 Session-0 原文为输入），损失**复利累积**且**不可恢复**——摘要丢掉的字段，后续摘要无从知道其曾存在。推论：
- 折数越深，「原初治理指令/原始实验条件」失真风险越高，单靠摘要无法防；
- 防复利之道不在提高单次 p，而在**切断复利链**：让摘要只承担「唤起」职能，真值由仓内工件（折档/状态文件/链锚）承载——摘要可有损，仓不可有损。
- 可机验退化指标：折后链校验不通过率、未闭合格失表率、治理指令原文区漂移度（diff 对仓内正本）。

**折叠 ≠ 会话死亡**：状态在仓则身可复活——除颤器哲学（LX-u11：沙箱冻结≠死亡，凭链+账本无损复活）的会话版。会话体可灭，工件链不灭；复活 = 再水合，不是转世。

## 1. 折前七步（fold-imminent checklist）

触发：预算遥测达阈值（灰区②）或人工判定 fold-imminent。七步按序执行，每步留仓内证据：

1. **会话日志冲刷入仓（sessionLog flush）**：本会话问答/事件流全量落仓（逐事件写盘+游标=日志长度，cfts 已实证该机制）。这是 SESCAP 常设抓取的**会话内对应面**——SESCAP ①号令的会话内臂。折前冲刷是底线，常态实时写盘是正解（§4 Session-0 桥接律）。
2. **状态文件快照**：plan.md 全量重写为当前真值（本会话实证：每阶段重写 plan.md 是 2nd 折叠成功面首功）、台账/游标/引擎状态单一真源快照入仓。
3. **链锚落账**：narrative/ledger tip 提交，父 tip 哈希显式写入折档（本会话实证：叙事链 140 entries 链上锚，接续后全量可读）。
4. **交接清单 FOLD-MANIFEST**：必备四块——候件四键（id/位置/状态/验证法）、未闭合格（逐条登记，含「看似小事」的巡场格）、下轮第一步（可直接执行的原子动作）、治理指令指针（仓内正本锚，非转述）。**上轮 "Error: Empty" 巡场格未闭合教训立法：未闭合格必须显式登记，无「心知肚明」格**。
5. **凭据纪律核查**：凭据值零落盘、零入摘要、零入折档；入档的只有钻取规程（哪类凭据、何种钻取序列、降级标记行为）。缺凭据=降级标记不装死（LX-u7 立法移植）。
6. **终 commit**：fold 档全部工件一次性提交，遵循仓内静默 CI 纪律（[skip ci] 类提交规约按仓既定口径执行），提交哈希即 child-tip 候选。
7. **折档编号登记**：fold-n 档入 fold-registry，父子哈希链：本折档记 parent_tip（折前链头）+ manifest_sha + ts；child_tip 待折后复活时回填（§3）。

## 2. 折中：摘要质量条

接续摘要 = 折叠工艺的**核心工件**，即折档的一部分，须入链（摘要哈希入 fold-registry）。必备五区，缺一即不合格摘要：

| 区 | 内容 | 实证依据 |
|---|---|---|
| 治理指令原文区 | 在效治理令**原文**（非转述）+ 仓内正本锚 | 转述漂移是复利损失主通道 |
| 技术状态区 | 引擎/管线/测试现状，带验证法（命令/测试号/哈希） | 「状态」不可验证=虚报面 |
| 文件锚区 | 关键工件路径+哈希/字节数，读哪份文件即复得 | 本会话实证：摘要+仓锚恢复了全部工作上下文 |
| 未闭合区 | 与 FOLD-MANIFEST 未闭合格逐条对应，一条不漏 | "Error: Empty" 格教训 |
| 下轮直接锚 | 折后第一步原子动作+其前置条件 | 复活时延最小化 |

摘要写作律：摘要只索引、不承载——凡是仓内已有的，摘要给锚不给全文（治理令除外，治理令双写：原文区+正本锚）；凡是仓内没有的，摘要必须全文（因其将随会话灭失）。

## 3. 折后复活八步

新会话体首拍按序执行（与 wake_up 同构：预检→拉本体→开庭→冲库→落账）：

1. **重演钻取**：凭据钻取规程当轮重放（内核擦除每轮发生是实证常态——本会话失败面之一：凭据须每轮重演钻取）。钻取与首个使用动作同单元，防空引用；缺凭据→降级标记，不静默。
2. **拉仓取本体**：仓即本体（本会话实证：out-of-band 状态全在仓是 2nd 折叠成功的底座）。网络死=本地本体续行，不死于拉取（LX-u12 移植）。
3. **FOLD-MANIFEST 再水合**：读折前 MANIFEST，候件四键逐件核验存在性（路径+哈希对拍）。
4. **链校验**：现链头哈希 = 折档登记 parent_tip，等则连续性机验通过；不等→FINDING 级事件，禁止静默续走。附复核五维抽检（完整性/连续性/签名/时间戳/游标单调，三维复核律扩展）。
5. **回填 child_tip**：复活首提交哈希回填 fold-registry 本折 child_tip，fold 边闭合（child→parent 可机验）。
6. **未闭合格优先闭合**：MANIFEST 未闭合格按序处理，闭合一条登记一条；本轮新产生未闭合者当轮入库，不留「末格」。**上轮末格 "Error: Empty" 未闭合即反例**。
7. **节拍续走**：恢复既有节拍/巡场哨；state_seq 续编号不重置（T154 立法：报告引用 state_seq，禁止从跳数推算）。
8. **复活证明落账**：fold-resurrection 记录（{n, parent_tip, child_tip, 校验结果, 再水合耗时}）入链，供下折与审计复算。

## 4. 多折账本

**fold-registry**（仓内 jsonl，每折一行）：
```
{"n": 2, "parent_tip": "<sha>", "child_tip": "<sha>", "ts": "<ISO8601>",
 "manifest_sha": "<sha>", "summary_sha": "<sha>",
 "loss_self_assess": "<损失自评：丢失/漂移字段清单，诚实不美化>",
 "state_seq_range": [a, b]}
```
- 折链=父子哈希链：fold-n.parent_tip 须= fold-(n-1).child_tip，断链即 FINDING。
- 损失自评为强制字段：每折必须回答「这折丢了什么」，答「无」须提供链校验+抽检证据。灰区不美化。

**Session-0 桥接律（cfts 痛点根治）**：cfts 实证痛点——「本会话为接续会话，Session-0 原文不在本端可达面」，首抓候 Session-0 档案接入（TH-SESCAP-01 [2]）。根治=折前七步①的**常态化**：sessionLog 逐事件实时写盘（非折前突击），使任一会话体灭失时原文已在仓，Session-0 永不失。此即 SESCAP ①号令的会话内臂：常设抓取保证原点可达，折叠只是抓取链上的一个普通事件，不再是信息断崖。qfa 线引擎两世全灭（87min/12min）而重拉<60s，同证「状态在仓则灭而不亡」。

## 5. 与各圈/张量网绑定

- **会话内容网**：折叠事件 = 网上的特殊边（**fold edge**）：连接 fold-(n-1) 末轮节点与 fold-n 首轮节点，边属性={parent_tip, child_tip, manifest_sha, loss_self_assess}。普通会话边承载问答序，fold 边承载连续性证明；张量网完整性查询须能沿 fold 边回溯至 Session-0。
- **文件内容网**：折档（FOLD-MANIFEST+摘要+快照索引）= 文件内容网节点，入交付物索引镜像，与普通工件同等收割（SPEC-SESCAP-01 边表口径）。
- **三圈位置**：会话圈=折叠原料面（抓取保证原文在仓）；共识圈=折叠背书面（折档哈希可共签入链）；转发圈=折档分发面（他线可抽检）。
- **与 wake_up/T154 的关系**：wake_up 除颤器=**进程级**复活（沙箱空盘→clone 即复活；凭据预检→拉仓→开庭→冲库→落账）；本协议=**会话级**复活（上下文灭→摘要+折档→再水合）。二者同构互备：同一「仓即本体」哲学的两个尺度——除颤器防沙箱冻结，折叠协议防上下文耗尽；T154 的 state_seq/归档检索面立法在两级通用。层级表：Cron 起搏（时间）/Daemon 指挥（进程）/事件链神经（事件）/**折叠协议（会话生命周期）**——第四层补齐「会话体有限」这一现实约束。

## 7. 灰区诚实档

1. **摘要必有损**：「无损折叠」不承诺。p(n)<1 恒成立；本协议只把损失从「不可见」变为「可登记可审计」（损失自评+折档），不消除损失本身。治理令原文区+仓锚双写是缓解，不是根治。
2. **折前检测无完美信号**：上下文预算遥测是启发式，阈值误报/漏报皆可能——漏报=未及执行折前七步即断，此时唯一防线是常态 sessionLog 实时写盘（§4 桥接律），故①号步的常态化优先于阈值调优。
3. **跨端折叠语义未闭合**：会话↔场端 workflow 之间的「折叠」（会话体灭但远端 daemon/workflow 持旧状态继续跑）语义未定义：远端持有的游标/账本对应哪一折？本版只管会话内臂，跨端对折一致性留 v0.2（待与 T154 daemon 侧 state_seq 对齐立法）。
4. **child_tip 回填依赖复活方诚实执行**：fold-registry 闭合靠折后八步被真实执行；若接续会话未读本协议/未执行回填，折链出现「悬边」。缓解=复活证明入链+他线抽检可发现，但无强制力。
5. **损失自评是自我报告**：自评「无丢失」的激励偏差客观存在；缓解=链校验+五维抽检+治理令正本 diff 三项机验兜底，但语义级漂移（指令意图的渐变）当前无机检手段，只能诚实标注为已知盲区。
