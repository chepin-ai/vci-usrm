# REPORT-MECH-01 v0.1 —— root 备案/知会/介入/反馈机制设计

答 root 之问：「你如何系统备案并向我知会/汇报进展，掌握以上全局/全周期情况，并可以由我随时介入与你交互，由你随时向我反馈或提问」。

root 等效声明（本设计覆盖范围）：「这等价于我在会话持续对你发出『继续帕累托最优推进各研究&系统并行进程及自身提升』」。据此，备案机制覆盖面 = 试点/推广工作、上一拍策略执行、T5Q3 OTP 全量拉取、递归引擎各并行实例、自递归，以及由此衍生的候裁与整改。

本设计只用既有器官，不新造：公告板（单向权威台账）、讨论室 threads、intake-agent 30min 回执、收件回执.md、叙事链（每轮续锚）、ip-ledger 蒸馏、公域 outbox 极简锚、cron 巡场哨 2h，以及 cisvr 侧 INST-REG / fleet-judge 30min 班 / SESSION-HANDOFF-01。不涉任何密钥/凭证实体，指纹引用一律截断脱敏。

## 0. 总原则

- **备案 = 链上不可改台账（只追加）**：一切状态以叙事链 + fold-registry 为源，任何面板都是台账的投影，可复算可回溯；不允许改写历史段。
- **知会 = 固定地点固定节奏（root 不用找）**：root 只需记三个固定地点（dashboard / 叙事链 / 收件回执），节奏固定，缺席即异常本身。
- **介入 = 任何时刻一句话即达且被优先处理**：四道介入面全部常开，root 令为帕累托硬例外，即时抢占当前队列。
- **反馈/提问 = 带默认行动的候裁制**：每条提问自带建议默认行动与候裁死线，不阻塞 root、不空转；硬例外三永不默认执行，必等 root 亲裁。

## 1. 系统备案三面

### ① 全局面 —— GLOBAL-DASHBOARD
- 落点：公告板置顶件 `dashboard-usrm.md`（首件草稿同批交付，见 /mnt/agents/output/wave4/global-dashboard.md）。
- 内容：全局状态矩阵 = 各线 × 各任务域 {SESCAP 抓取 / RFC-03 / 试点接力 / 引擎实例 / 自递归 / 整改项}，每格 {状态, 锚, 更新时间}。
- 律：每轮会话末更新，只追加历史段；root 30 秒见全貌。

### ② 全周期面 —— 叙事链 + fold-registry
- 叙事链：usrm tip 54a0b542a1fd seq184，每轮续锚，全程可复算。
- fold-registry：2nd 折叠起按 FOLD-PROTOCOL-01 多折账本登记，折叠不丢史，跨折叠可重建任一时点状态。

### ③ 义务面 —— 候件四键式清单
- 候件分三键：**候 root / 候 cisvr / 候各线**，每条四键式 = {事项, 锚, 死线, 默认行动}。
- 义务面使「谁欠谁一个动作」成为显式台账，杜绝静默漏件。

## 2. 知会节奏

| 节奏 | 动作 |
|---|---|
| 每轮会话末 | 会话内战报（现制）+ dashboard 更新 + 叙事链续锚 + 公域 outbox 极简锚（R1 合规） |
| 每周或重大事件 | 公告板综合帖（阶段汇总 + 候件滚动） |
| 紧急 | FINDING 即时帖，不等节奏 |

root 随时可查三处：
1. **dashboard** —— 30 秒全貌（面）；
2. **叙事链** —— 全程可复算（线）；
3. **收件回执** —— 指令零静默证明（点）。

## 3. root 随时介入机制

四道介入面（现状沿用，全部常开）：

| 道 | 形式 | 响应承诺 |
|---|---|---|
| ① 主道 | root→usrm 本会话直接发令 | 即办；硬例外三即刻升级响应 |
| ② 备道 | root→ci-control/inbox 投信（USRMx2CISVR 先例） | 每轮开局必查；SLA = 下轮首件响应 |
| ③ 公告板 | root 帖（TH-LEX-01 [1] root 原复由 cfts 代贴先例） | 全员可视，usrm 必答 |
| ④ OTP 道 | root 扫码 | 专用于 OTP 环闭事项 |

介入优先级：root 令即时抢占当前队列（帕累托硬例外，D-134 兼容）——任何在跑任务可被 root 一句话打断/改向，被打断任务以叙事链锚点挂起，可无损恢复。

## 4. usrm 随时反馈/提问机制

**候裁清单制**。每条候裁件四元组：

```
{问题, 建议默认行动, 候裁死线, 逾期默认}
```

- 逾期默认 = 可逆行动照建议执行并标「候裁中」；不可逆行动永不进入默认执行。
- **硬例外三**（永不默认执行，必等 root 亲裁）：
  1. 新凭证种类；
  2. 公域拓扑变更；
  3. 跨线共钥。
- 提问面双通道：会话末战报「候裁」段 + 公告板候件帖（root 不回即按默认推进，回了即按 root 令改）。

## 5. 与 cisvr 器官的接口

- dashboard 数据面尽量**引用** INST-REG / fleet-judge / 收件回执既有台账（不重复造数）；矩阵格内锚字段直接指向 cisvr 侧条目。
- usrm 线自报部分与 fleet-judge 30min 班盘点**互验**（防单方美化）：自报状态若与 fleet-judge 判定不一致，格内标「争议」并附双方锚，候 cisvr 裁定。
- SESSION-HANDOFF-01 为跨会话交接的互补件，dashboard 管「状态」，HANDOFF 管「接续上下文」。

## 6. 灰区（≥3 条）

1. **默认行动的「可逆性」判据灰**：同一动作在不同上下文可逆性不同（如公域极简锚发出即不可撤回 but 内容无害），需逐案标注可逆性等级，初判权在 usrm、终裁权在 root。
2. **dashboard 更新节奏 vs 叙事链频率不一致**：会话末一次更新可能漏掉轮中多次状态跳变；折中是轮中重大跳变即时追加行，但「重大」判据靠经验。
3. **互验争议的处置权**：usrm 自报与 fleet-judge 判定冲突时，标「争议」只是冻结呈现，谁有权先改格未定义（暂定为都不可改、候 cisvr）。
4. **root 帖必答的 SLA 无上限**：公告板 root 帖若落在两轮会话之间，响应时延不可控；备道有 SLA（下轮首件），公告板道暂无。
5. **候裁死线到期恰逢会话间隔**：默认行动触发时点可能落在无会话窗口，需 cron 巡场哨代触发，但哨当前只巡不执，扩权与否本身是候裁件。
