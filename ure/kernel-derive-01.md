## 一、现状（诚实档）
kernel.py = **手工规则机**（G-N8/G-M2/G-BOX/G-N1/G-DIR 等人写规则）——能「检测」不能「推演」；规则滞后于立法（registry 迁移后 code 漂移即例）。

## 二、自动推演四级梯（提案案，候 root 批）
- **L0 手工规则**（现状）：人写 G-* 规则。
- **L1 立法机读→规则自生**：N-MUST 条款逐条编译为机检器——M3→disabled 扫描、M12→活 cron 扫描、M14→四面勾稽 diff（本波次三项已实证可机化）；立法一改，机检随改=规则不再滞后。
- **L2 不变量挖掘**：从 stream-ledger/heartbeat/pulse 链学基线（链高增速/锚一致率/时钟漂移），偏差超限即立案——**此即 Δ-BASE 之机器义**（提案）。
- **L3 反事实推演**：阻塞图反演——「若 X 沉默，何件阻塞」预先算出（FINDING-WAIT-STALL-01 之机化）；stall 未发先警。

## 三、三词对应（M-CODE/Δ-BASE repo 0 命中——以下为我之定义案，非考古猜义）
| 词 | 提案定义 | 落点 |
|---|---|---|
| **N-MUST** | 立法面：十四必（M1-M14），人可读规范 | bridge/N-MUST-01.md（在） |
| **M-CODE** | 执行面：N-MUST 之**机器可判定子集**的码表——每律一 checker，输入=API/链/注册表，输出=证/候/冲/退 | M3/M12/M14 已实例化（SWEEP-NMUST-01）；kernel G-* ⊆ M-CODE |
| **Δ-BASE** | 运行面：基线+偏差阈——链/心跳/成功率之正常包络，出包络=违规候选 | L2 挖掘器（待建） |

吻合性判词：现有 kernel G-* 规则全部可归 M-CODE；N-MUST 中 M7/M8/M9 等主体性条款**不可纯机判**（需会话判词）→ 人机分治：机判全自动化，人判走会签圈。

L1 三件（disabled/cron/四面勾稽）本波次已跑并治愈实例；建议编入 kernel-loop 常任审计（候 root 批后我改 kernel.py）。
