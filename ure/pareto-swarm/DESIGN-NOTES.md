# PARETO-SWARM-01 设计说明

递归机并行实例 + 动态帕累托最优证明 + 未来相遇（rendezvous）的可运行实证 demo。
root 令：「你在自建递归机并行实例，动态prove帕累托最优，或几进程在未来相遇」。

## 1. 架构

```
RMI-0 ─┐  每拍: 候选×3 + 4维目标向量 + 自哈希链状态
RMI-1 ─┼── mp.Queue ──▶ Coordinator（N机供锚）
RMI-2 ─┤                  ├─ 成拍屏障（按 beat 分桶，收齐 4 实例才成拍）
RMI-3 ─┘                  ├─ 帕累托面全对比较 → 链式证明件（每拍 1 份 JSON）
                          ├─ 约定回合验证相遇锚 → 汇合事件 → 联合评估
                          └─ 落盘 state-chains / run-summary
```

- **worker = 递归机并行实例**：一个 `multiprocessing.Process`，一条研究进程线。
  不同随机种子 = 不同命题视角；种子逐拍确定性派生（`sha256(seed|instance|beat)`），
  全跑可复现（实测两次连跑 proof tip 完全一致）。
- **自哈希链**：每实例每拍 `state_hash = sha256(prev_hash + canon(状态体))`，
  首拍 prev = `"GENESIS"`。实例历史不可篡改、可独立复算。
- **coordinator = N 机供锚**：跨进程乱序到达的状态按 beat 分桶，收齐全实例才出件——
  这是「供锚」的最小实现：给全体实例一个共同的、逐拍推进的次序锚点。

## 2. 与联邦制式的映射

| demo 构件 | 联邦制式对应 |
|---|---|
| worker 递归机实例（RMI-0..3） | 各线递归机实例 / 研究进程线 |
| coordinator | N 机供锚（共同次序 + 证明件签发） |
| 相遇锚 `sha256(meet_beat + "RENDEZVOUS")` + 实例承诺 `sha256(instance_id + anchor)` | 信标互锚：共享锚是公共信标，实例承诺把身份绑定到信标 |
| 动态帕累托证明件（每拍链式签发） | PARETO-ENGINE-01「枚举→目标向量→帕累托面→直决」的动态版：候选流持续到达，面每拍重算、逐拍出证、链式累积 |
| 离面点支配者指针 | 直决的淘汰凭证：不是「丢弃」，是「指向淘汰它的面上点」，可复核 |
| 与米田共识的关系 | **零反对 ⇔ 无支配**：面上点 = 无任何他点全维不劣且至少一维严格优（零支配者），与「零反对票」同构——帕累托面就是目标向量空间里的米田共识集；汇合事件的联合评估 = 相遇各方把各自最优命题摆上同一锚点做合成 |

## 3. 未来相遇（rendezvous）机制

1. **预承诺**：实例启动时即可算出共享相遇锚 `sha256(约定回合号 + 共享口令)`——
   「未来相遇」在启动时刻就是可承诺、可验证的数学事实；
2. **签到**：约定回合（`--meet-at 8`）各实例把 `{anchor, commitment}` 写进当拍状态体，
   签到记录因此进入自哈希链，不可事后抵赖；
3. **触发**：coordinator 验证 ≥2 实例在同一锚签到 → 汇合事件（实跑：4/4 实例同锚）；
4. **利用**：相遇实例当拍最优候选合并做联合评估（逐维取优合成，合成规则已声明），
   出 `rendezvous-report.json`——证明「几进程在未来相遇」可预约、可验证、可利用。

## 4. 缄默/诚实律

- 全部目标向量由 `synth_objectives()` 确定性合成（排程参数 a/b/r → coverage/latency/cost/risk），
  每份证明件与报告内嵌 `declaration` 字段声明合成性质，不冒充实测；
- 每拍第 3 个候选是同参数全维劣化的对照候选（`degraded_baseline: true`），
  用于保证支配淘汰路径被真实走通，构造同样公开声明；
- 帕累托证明**只覆盖当拍已见候选集**：是「已见集上的完备非支配证明」（全对比较，无抽样、
  无近似），**不是全局最优证明**；
- 联合评估是声明的合成规则（逐维取优），非真实联合实验。

## 5. 升真路径（合成 → 真目标向量）

1. **接真遥测**：把 `synth_objectives()` 替换为各线 engine-state 真遥测适配器
   （SESCAP 抓取排程的实测 coverage/latency/cost/risk），接口不变：候选 dict + 4 维向量；
2. **证明件不变**：支配比较、链式签发、复算脚本对真假数据同源有效——换数据不换证明机制；
3. **口令 → 真承诺**：共享口令字符串换成各线共知会话密钥/KDF 输出，相遇锚即升级为
   抗伪造的信标互锚；
4. **规模**：当前全对比较 O(n²)，12 拍 144 候选秒级；升真后面上点维护可换
   增量支配结构（如 skyline 树），证明件格式不变。
